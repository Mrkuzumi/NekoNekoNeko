## 1.1 代码理解与需求反推（写在答题卡中）

### 给 AI 的提示词
```
请用 C 语言写一个命令行程序：
读取一个整数 n（1 ≤ n ≤ 100）表示学生人数，然后读取 n 行数据，每行 5 个整数：
学号、发帖数、评论数、礼物数、迟到次数。
按以下公式计算每位学生的活跃分：
score = 发帖数 × 0.01 + 评论数 × 2.5 + 礼物数 × 8.0 - 迟到次数 × 1.5
若得分为负则计为 0。
程序输出四部分：
1. 平均分（保留两位小数）
2. 三个等级人数：hot（≥300）、warm（≥100）、cold（<100）
3. 最高分学生学号及得分（保留一位小数）
4. 最低分学生学号及得分（保留一位小数）
5. 所有学生按得分降序排列（得分相同按学号升序），每行输出学号、发帖数、评论数、礼物数、迟到次数、得分。
输入合法性要求：n 不在范围内或无有效输入时直接结束；任一项指标为负时直接结束。
```

### 初学者/AI 容易忽略的细节
- **`score[i] < 0` 归零发生在累加 `sum` 之前还是之后？** 当前代码先归零再加，归零后的 score 参与平均值和排序。如果归零逻辑放错位置（如在累加 sum 之后才归零），avg 会偏小，排序结果也会不同。
- **排序稳定性**：冒泡排序中 `score[j] == score[j+1] && no[j] > no[j+1]` 的次级比较条件，AI 可能写成 `<` 而非 `>`，导致学号排序方向相反。
- **`#define MAXN 100`** 是硬编码上限，AI 可能忽略边界检查。

## 2.1 会停下来的小球 — `q2_1.c`

### 算法
```
读取 h, p, q
landings = 0
total_distance = 0
current_height = h

循环：
  landings++
  total_distance += current_height        // 下落
  rebound = (current_height * p) / q      // 整数除法即向下取整
  if rebound == 0: break
  total_distance += rebound               // 反弹上升
  current_height = rebound

输出 landings 和 total_distance
```

### 关键点
- 整数运算自动向下取整，无需 `floor()`
- 总路程 = 每次下落 + 每次有效反弹上升
- 最后一次落地后反弹为 0，不加上升距离
- 严格输出两个整数，无多余文字

### 验证
样例 `100 1 2` → `7 294` ✓

## 2.2 欧姆定律实验记录 — `q2_2.c`

### 算法
```
读取 n, R, limit
初始化 valid = 0, pass = 0, fail = 0
sumU = 0, sumI = 0
min_error = 很大的数, min_index = -1

遍历 i = 1 到 n:
  读取 U, I, flag
  if U <= 0 或 I <= 0 或 flag != 0: continue  // 无效
  valid++
  sumU += U; sumI += I
  error = abs(U - R * I)
  if error <= limit: pass++
  else: fail++
  if error < min_error:
    min_error = error; min_index = i

输出：
  第一行: valid pass fail
  第二行: sumU sumI
  第三行: if valid == 0 → "-1 0" else → "min_index min_error"
```

### 关键点
- 记录编号从 1 开始
- 误差并列时取较早出现的（用 `<` 不用 `<=` 即可）
- 无效记录不参与任何统计
- 无有效记录时输出 `-1 0`

## 3.2 自走棋阵容经营模拟器 — `q3_2.c`

### 游戏设计

#### 棋子系统（≥3 种）
| 棋子 | 费用 | 职业 | 阵营 | 基础攻击 | 基础生命 |
|------|------|------|------|---------|---------|
| 剑士 | 1金 | 战士 | 人族 | 50 | 500 |
| 弓手 | 2金 | 射手 | 精灵 | 70 | 350 |
| 法师 | 3金 | 法师 | 精灵 | 90 | 300 |
| 骑士 | 4金 | 坦克 | 人族 | 40 | 800 |
| 刺客 | 3金 | 刺客 | 暗影 | 100 | 250 |

#### 阵营/职业羁绊
- **人族(2)**：所有人族 +100 HP
- **精灵(2)**：所有精灵 +20% 攻速
- **战士(2)**：战士 +30 攻击
- **法师(2)**：法师技能伤害 +50%
- **坦克(1)**：坦克 +300 HP
- **刺客(2)**：刺客暴击率 +25%
- **射手(1)**：射手攻击距离 +1

#### 操作（≥4 种）
1. **刷新商店** — 花费 2 金刷新可选棋子（5 个栏位）
2. **购买棋子** — 花费对应费用购买，同名 3 个自动升星
3. **出售棋子** — 按费用半价回收
4. **升级人口** — 花费递增金币，提高上场人数上限
5. **上阵/下阵** — 管理场上阵容
6. **装备道具** — 购买/装备道具到棋子

#### 经济系统
- 每回合基础收入 5 金
- 利息：每 10 金 +1 金（最多 +5）
- 连胜/连败额外金币

#### 战斗系统
- 双方按攻速轮流攻击
- 伤害 = 攻击力（考虑羁绊加成）
- 存活棋子多的一方获胜
- 输方扣除血量 = 对方存活棋子数 × 2

#### 命令行输出格式
```
=== 第 N 回合 ===
金币: 25 | 等级: 5 | 人口: 3/5 | HP: 80
--- 商店 ---
1. 剑士(1金) 2. 弓手(2金) 3. 法师(3金) 4. 骑士(4金) 5. 刷新(2金)
--- 阵容 ---
[战士] 剑士★★ ATK:80 HP:600 | [射手] 弓手 ATK:70 HP:350
--- 激活羁绊 ---
战士(1/2) 射手(1/1)
请输入操作 >
```

### 函数划分
- `init_game()` — 初始化
- `refresh_shop()` — 刷新商店
- `buy_chess()` — 购买棋子
- `sell_chess()` — 出售棋子
- `level_up()` — 升级人口

- `calc_synergy()` — 羁绊计算
- `show_status()` — 显示状态

### 测试样例
1. 开局购买 3 个剑士升 2 星 → 验证升星逻辑
2. 触发双人族羁绊 → 验证羁绊加成
3. 连败 3 回合后经济检查 → 验证连败金币

### 输入格式
- 操作通过单字符 + 参数输入，如 `b 2` = 购买商店第 2 个棋子, `s 1` = 出售备战区第 1 个棋子, `r` = 刷新, `l` = 升级, `d 1 3` = 将备战区第 1 个棋子放到棋盘第 3 位, `n` = 下一回合, `q` = 退出
